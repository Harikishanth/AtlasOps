## Summary

The GitHub October 2018 incident lasted 24 hours and 11 minutes, affecting every GitHub
service globally. The root cause was a MySQL primary-replica failover loop triggered by
a network partition — replicas couldn't determine which was authoritative, so they cycled
continuously. AtlasOps replayed this pattern against redis-cart (acting as the stateful
primary) with a 2-minute kill cycle. The Diagnosis agent correctly identified the failover
loop pattern — not a simple pod crash — in 4 tool calls. Resolution required both stopping
the chaos experiment AND preventing automatic Kubernetes restarts from recreating the loop.
Total time: 6m 44s. GitHub's original incident: 24h 11m.

## Root Cause

A PodChaos experiment (`hist-github-2018-redis-kill`) killed redis-cart on a 2-minute cron
schedule, simulating a primary-replica failover loop. Kubernetes automatically restarted
redis-cart, but cartservice's connection pool did not re-establish fast enough between kills,
creating a continuous degraded state rather than a clean recovery.

**Key diagnostic insight:** The Diagnosis agent correctly distinguished this from a simple
OOM kill by observing:
1. Restart count was increasing at a regular interval (not random)
2. No memory pressure visible in `kubectl_top_pods`
3. No CrashLoopBackOff (pod was completing a full start before being killed again)
4. `kubectl get podchaos -n chaos-mesh` revealed the active experiment

## What Went Well

- Diagnosis agent identified the chaos experiment directly — did not attempt a rollback
- Correct root cause in 4 tool calls, 95 seconds from alert receipt
- No unnecessary restarts, scale operations, or silences attempted
- Remediation was minimum-blast-radius: delete the experiment, nothing else

## What Went Wrong

- Triage classified P0 immediately without checking if chaos-mesh had active experiments
  (a faster first check would have saved 30 seconds)
- cartservice connection pool recovery after redis stabilisation took longer than expected
  (20 seconds post-chaos-delete before errors cleared)
